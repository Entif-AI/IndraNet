# Open work

This ledger captures repo-relevant unresolved work stated or implied by the v0.5.0 manuscript, implementation and validation receipts. Items are written as testable work rather than as claims that the result already exists.

## Standards-runtime study

- Execute the preregistered native-server comparison against real NGSI-LD and SensorThings implementations and an appropriately authorized locating/omlox surface.
- Run full JSON-LD processing and a complete SHACL engine for the declared profiles.
- Exercise native VDA 5050, OpenXR, ROS/tf2 and OpenUSD integrations where the corresponding use case requires them.
- Record round-trip loss, server behavior, version-specific divergence and unsupported semantics without converting a successful existing-standard profile into an artificial failure.

## Independent implementation and conformance

- Produce an implementation independent of the current Python reference and compare canonical records, revisions, purpose views and negative cases.
- Resolve whether the candidate Pack belongs in Rosetta, remains a separate project contract, or should be decomposed into smaller public profiles.
- If Rosetta adoption proceeds, obtain the appropriate maintainer review and identifier allocation instead of treating the local candidate ID as canonical.

## Physical and vendor interoperability

- Exercise live locating, robotics, XR and media endpoints under explicit authorization and safety constraints.
- Separate transport success, semantic preservation, timing behavior and actuation authority in the resulting receipts.
- Add clock, frame and calibration evidence for live physical sources rather than inheriting fixture assumptions.

## Generative Reality research

- Build or integrate a receiver that can consume a prior world package, dynamic state and appearance witnesses.
- Define task-specific evidence-faithfulness metrics before measuring compression or perceptual benefit.
- Compare total communication cost, update latency, reconstruction quality and degradation behavior against relevant baselines.
- Test witness loss, stale priors, invalidated derivations and unsupported appearance explicitly.

## Security, privacy and operations

- Replace fixture keys and caller-supplied grants with an authenticated production authority model before operational use.
- Define distributed revocation, deletion/retention behavior, key rotation, replay handling and multi-process consistency.
- Threat-model purpose grants, stale or malicious evidence, identity linkage and cross-context inference.
- Evaluate privacy mechanisms empirically where a use case claims privacy properties; illustrative suppression alone is not an anonymity or differential-privacy result.

## Publication and review

- Complete author/IP/license review for the public candidate.
- Obtain independent technical review rather than treating internal adversarial review as external validation.
- Run full browser, mobile and assistive-technology QA for any publication site that presents the manuscript or interactive fixtures.
